## Pipeline

1. **Source pack** `scripts/notes/.sources/<id>.json` (gitignored). `build-sources.ts` needs a service-role key we do not have, so writers build packs by hand with read-only SELECTs through the Supabase MCP (project `peohauhwquuvghrpmotf`). The packs from this session are partial/curated and may be lost with the container; rebuild them if you must re-check a note.
2. **Writer** drafts `scripts/notes/drafts/<subject>/<id>.json` (`written_by "sonnet-5-5"`, `status "draft"`). Validate: `bun run scripts/notes/validate.ts <subject> --ids ...`. Instructions: `WRITER_INSTRUCTIONS.md`.
3. **Science checker** fixes in place and signs: `meta.checked_by = "sonnet-science-check"`, `meta.checked_at = "2026-10-01"`. Instructions: `CHECKER_INSTRUCTIONS.md`. Nothing unsigned goes live.
4. **Load** to `public.notes` (status `approved`, `approved_at` set) via MCP only. `python3 scripts/notes/handover/make_load_sql.py <ids_in_db.txt> <out_dir>` writes `<id>.sql` and `manifest.tsv` (md5 + length) for signed notes not already in the DB. One loader agent per ~9 notes using `LOADER_PROMPT.md`; it checks `md5(body::text)` against the manifest. Insert uses `on conflict do nothing`, so it never overwrites.

Subagent cap is 20 concurrent. The Stop hook commits and pushes the working tree each turn.

## Known loader failure mode and fix recipe

Loader agents occasionally retype a note with a one-character error; the md5 check catches it. Do not re-run the file (`on conflict do nothing`). Fix with a surgical update, e.g. `update public.notes set body = body #- '{meta,x}', updated_at=now() where concept_id='...' returning md5(body::text);` or `jsonb_set(body,'{path}', to_jsonb(replace(...)))`, then re-compare md5.

## Lessons baked into the writer/checker instructions

- Every mistake must be backed by a mark-scheme ignore/reject rule; exam phrases are mark-scheme wording, not answers or equations.
- Worked examples must stand alone (inline figures/tables) and come from the concept's own pack; never reuse one in two notes. Multiple-choice options must be fetched from the DB.
- Practice/slider ranges must be realistic at both ends, no rounding ties.
- Higher / Separate labels follow the concept data and spec, not board names in shared text.
