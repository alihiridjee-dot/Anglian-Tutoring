## 6. Argon review: fix plan (checked 17 Oct, nothing fixed yet)

An automated reviewer (Argon) listed 31 issues on 17 Oct. Every claim was checked against the code and the live database. Seven are worth fixing. About a third are false or already fixed. No PR exists for any of them (checked 27 Oct). The three cards proposed on 17 Oct were never started.

**Fix, in this order**

1. **#2 Editing a task can wipe it.** Confirmed on live. `src/components/tutor/HomeworkForm.tsx` reads the task, its questions and its spec links with `Promise.all` and never checks `.error`. If the questions read fails, the form opens empty. Saving calls `save_homework_brief`, which deletes every question not sent (`id <> all(_kept)`), and `homework_answers` cascade. Students lose answers and marks, with no undo. Tutor-only and rare. Fix: open the form only when all three reads worked; otherwise show `ErrorNote` with Retry.
2. **#17 An AI draft can land in the wrong child's chat.** `ThreadView.tsx` `draft()` sets the body after the AI call returns without checking the thread is the same. Neither parent keys it by thread. Fix: `key={selected.id}` in `routes/_authenticated/messages.tsx` and `components/parent/ParentMessages.tsx`.
3. **#3 Quizzes ignore paid subjects.** Confirmed on live. The `mcq_sets read` and `mcq_questions read via set` policies and `grade_mcq_attempt` check `viewer_has_content_access` but never the subject. A one-subject student can open other subjects' quizzes; a parent can grade quizzes and get the answer key. Fix: a migration gating on `private.my_content_subjects()` (fall back to the spec point's subject when `mcq_sets.subject` is null), and grading refuses non-students. Keep the weekly retake lock. Apply only after Ali's yes.
4. **#1 Demo data in a real account.** `useEnrolments` has the fixed key `["user-enrolments-and-profile"]` (10 min fresh) and decides demo vs live inside the fetch. A signed-in user who goes home page → demo → back in the app can see Alex's subjects for up to 10 minutes. Signing in from the demo only flashes it. Found by reading code, not reproduced. Fix: in `__root.tsx`, reset the query cache whenever navigation crosses into or out of `/demo` (one place, instead of the 34 files that check demo mode). Keep the `authChange.test.ts` rule that a first sign-in keeps public data.
5. **#10 Curriculum can show the wrong board.** `CurriculumPage.tsx` loads Edexcel GCSE first, then the student's board; the older reply can land last. Fix: a request counter so only the latest load sets topics.
6. **#4 Three tutor AI tools have no hourly cap.** `generateHomeworkQuestions`, `replaceMcqQuestions` and `generateChatDraft` never call `claim_ai_request`. Fix: use `requireTutorAi` (`tutorAi.server.ts`, 60 an hour); add any new kind (e.g. `chat_draft`) to `claim_ai_request`'s list by migration. Don't test with real paid calls.
7. **#24 Password minimum.** Sign-up (`AuthForms.tsx`) and `/reset-password` accept 6; `/profile` needs 8. Use 8 on sign-up and reset, not sign-in. Ali changes the Supabase dashboard minimum.
