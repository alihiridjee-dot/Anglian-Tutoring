# Structural overhaul: where things stand (22 September 2026)

Written for the next session. Read this before touching the codebase.

## Ground rules that were set

- No behaviour change. Every commit was checked with: `tsc`, `bun test src`
  (262 tests), `bun x eslint .` (11 pre-existing errors in 4 files, never
  more), `bun run build`, and where a UI file moved, a browser check.
- One section per commit, one or two sections per PR, merged with merge
  commits so each step can be reverted on its own.
- Never `git add -A` in this folder: other sessions leave uncommitted edits
  in it. Stage by path.
- Never run `supabase functions deploy`. Ali deploys.

## What is resolved (all merged into `main`, up to commit 72848b2)

**Dependencies and layout (PRs #55)**

- The one real import cycle and all six places where `src/lib` imported from
  `src/hooks` are gone.
- `src/lib` is grouped into domain folders (auth, billing, chat, curriculum,
  homework, mcq, planner, live, leads, profile, shell, platform). No file was
  renamed, only moved. `src/lib/utils.ts` stays put because `components.json`
  pins shadcn to that path.
- ESLint now enforces `lib -> hooks -> components -> routes`. An upward
  import is a lint error.
- The nine guarded routes that a `/demo/*` route also mounts are 7-24 line
  shells; their pages live in `src/components/<domain>/*Page.tsx`. Nothing
  under `src/` imports from `src/routes/` any more.
- Nine 350-420 line components were split into a `useX` hook plus small
  part files: `ThisWeekPanel`, `WeekReview`, `RoadmapPanel`, `Live`,
  `AuthPage`, `TutorTake`, `LiveForm`, `TutorPlannerPanel`, `PlanStep`.

**Planner engine (PRs #55, #56, #57)**

- `loadRoadmap`, `planForWeek` and `refreshWeek` each have characterisation
  tests (31 snapshots in `src/lib/planner/*.characterization.test.ts`) that
  record the result and the ordered log of every read and write. They were
  committed from the untouched code first.
- All three are now thin I/O shells over pure functions: `buildRoadmap` in
  `planner/roadmap.ts`; `selectWeek`, `unsupportedReviews` and `mergeWeek`
  in `planner/weekCut.ts`. `WeeklyPlanDAL` was cut from 917 to 462 lines by
  moving its unrelated reads into `WeeklyActivityDAL`, `WeeklyNotesDAL` and
  `PlannerRosterDAL`.
- Rule now in `architecture.md`: DALs call each other through the class
  (`WeeklyPlanDAL.getPlan`), never by direct function reference, so test
  spies keep intercepting. When moving a spied method, make the spy throw
  and confirm the dependent test fails.

**Edge functions (PRs #58, #59, #60, #61)**

- `bun run check:functions` typechecks all five with Deno, and
  `.github/workflows/edge-functions.yml` runs it on any PR touching
  `supabase/functions/`. This is the repo's first CI job. Six pre-existing
  type errors were fixed with annotations only.
- `supabase/config.toml` had an `[auth.security]` block the CLI rejects.
  It made every `supabase functions deploy` fail with "failed to parse
  config", probably since the July scaffold. Removed.
- `supabase/functions/_shared/` holds the helpers that were byte-identical
  copies across four functions (`http.ts`: CORS headers and `HttpError`;
  `clients.ts`: `admin()` and `stripeClient()`).
- `stripe-checkout` is 812 lines, down from 1,028: `auth.ts` holds the
  caller and authority rules, `customers.ts` the customer and household
  lookups.

**Bugs found along the way, all fixed**

- No test ever ran the real `loadRoadmap`; every test stubbed it.
- `guardState.test.ts` leaked its Supabase mock into every later test file
  (bun's `mock.module` is process-wide). It only passed by luck of folder
  depth.
- Dead code: `fmtRange`, several unused imports, a `covered ? X : X` ternary.
